## Summary

- Add a `bounty.yml` GitHub issue form to the website repo for centralized bounty admin.
- Add `bounty-sources.yml` so tracked bounty source repos are configured outside the sync script.
- Add `scripts/sync-bounties.mjs` to query issues labeled `bounty`, parse issue-form markdown, derive board state, and update `src/data/bounties.generated.json`.
- Add a manual-only `workflow_dispatch` Action to run the sync and commit generated data only when it changes.

## Notes

This is PR 2 of the bounty issue → bounty board pipeline and is stacked on top of PR #164.

V1 uses `Arrow-air/website` as the bounty admin surface. Bounty issues live in the website repo; actual deliverables and implementation PRs can still live in project repos like `project-longshot` or `project-quiver` and be linked from the bounty issue.

The workflow is intentionally manual-only for now. After we run it once and verify the generated diff, a follow-up can add cron scheduling.

The sync emits GitHub workflow warnings for malformed bounty issues and continues processing the rest, rather than silently corrupting the board.
