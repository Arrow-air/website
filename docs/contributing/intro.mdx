# Getting Started

Arrow is a global community building open-source aircraft. No gatekeeping, no approval process. If you want to contribute, you can start today.

:::tip
You don't need permission to start. Just communicate with the community so you stay aligned on what's actually needed.
:::

<Steps>

  <Step title="Read the docs">
    Spend 20 minutes getting a basic picture of what Arrow is and how it operates before jumping into Discord or GitHub.

    - [What is Arrow?](/docs/overview/about-arrow) — Mission, structure, the short version
    - [Our Projects](/docs/overview/our-projects) — Quiver, Spearhead, what's in development
    - [How We Work](/docs/contributing/how-we-work) — Async culture and how decisions get made
    - [Why a DAO?](/docs/governance/why-a-dao) — Why we're organized this way
  </Step>

  <Step title="Join Discord">
    [Discord](https://discord.com/invite/arrow) is where Arrow actually lives. Meetings, coordination, hardware updates, off-topic chatter. It all happens there. Drop into **#community-chat** and say hi.

    We hold regular community calls announced in the events tab. These are the fastest way to get a feel for the project and meet people. No agenda required to attend.

    <DemoImage src="/img/getting-started_discord.png" alt="Arrow Discord server" />
  </Step>

  <Step title="Browse the DAO forum and YouTube">
    Before jumping into work, read through some of the ongoing conversation.

    The **[DAO Forum](https://dao.arrowair.com)** is where governance proposals, grants, and project discussions are posted publicly. Reading through a few recent AIPs shows you how Arrow actually makes decisions and what's getting attention right now.

    The **[YouTube channel](https://www.youtube.com/@ArrowAir)** has flight test footage, build videos, and demos. Seeing the hardware fly makes the whole thing feel less abstract.

    <DemoImage src="/img/getting-started_dao-forum.png" alt="Arrow DAO Forum" />
  </Step>

  <Step title="Find something to work on">
    Arrow needs help across a wide range of areas. You don't have to be an aerospace engineer.

    We regularly need people with skills in mechanical design and CAD, electronics and PCB work, software (embedded, web, companion computer, ground control), flight testing, documentation, and video production. If you have a skill and want to use it, there's probably something useful you can do.

    **Don't have expensive tools?** Most design work happens in software — CAD tools like Fusion 360 and OnShape have free tiers, and all electronics work uses open source tooling. For hardware, most builds can be done with basic workshop tools or on-demand services like local makerspaces and PCB fabs.

    **Not sure how much time you have?** However much you can give. Some contributors are here daily; others drop in once a month. Both are genuinely valuable. Arrow works because small contributions compound.

    If you're not sure where to start, some genuinely easy first contributions: fix a typo in the docs, test a guide and report what's confusing, answer a question in Discord, or leave a comment on an open PR.

    For funded work, browse open bounties on the [Bounty Board](/bounty) or the [DAO Forum](https://dao.arrowair.com). If you want to build hardware, we loan out Quiver dev-kits to contributors developing attachments. See the [Project Quiver](/quiver) docs for details.
  </Step>

  <Step title="Sign the CLA">
    One thing you do need before any PRs can be merged: sign the Contributor License Agreement. It takes about a minute and only needs to be done once.

    **[Sign the CLA](/docs/contributing/sign-cla)**
  </Step>

  <Step title="Read the guides">
    If you're contributing code or documentation, these are worth reading before you submit anything.

    - [Development Guide](/docs/guides/development-guide) — Git workflow, branching conventions, commit style, local setup
    - [Writing Style Guide](/docs/guides/style-guides/writing) — How docs are written at Arrow
    - [Code Style Guides](/docs/guides/style-guides) — Python, TypeScript, Rust conventions
    - [Brand Guidelines](/docs/contributing/arrow-brand) — Logos, colors, how to represent Arrow

    **Tools:**

    | Tool | What it's for |
    |------|--------------|
    | [Discord](https://discord.com/invite/arrow) | Chat, meetings, coordination |
    | [GitHub](https://github.com/Arrow-air) | Code, hardware designs, issues |
    | [DAO Forum](https://dao.arrowair.com) | Governance, grants, proposals |
    | [Arrow Drive](https://drive.google.com/drive/folders/1efLrzqsiajzlxXiOUjxPT53CkfDGC0Yu?usp=sharing) | Presentations, brand assets |
  </Step>

  <Step title="Add your contributor profile (a good first PR)">
    Adding your profile to the [Contributors](/docs/contributing/contributors) page is a solid first PR. It gets you through the full contribution workflow without any pressure, and it puts your name in the record.

    1. Copy the [contributor template](https://raw.githubusercontent.com/Arrow-air/website/main/docs/contributing/contributors/_template.md)
    2. Go to the [contributors directory](https://github.com/Arrow-air/website/tree/main/docs/contributing/contributors) on GitHub
    3. Click **Add file**, then **Create new file**
    4. Fill it out and open a PR against `staging`
  </Step>

</Steps>
